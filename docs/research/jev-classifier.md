# Jev (TypeSafe AI) — System One model, применение к extraction/classification

Статус: research, источник — официальный сайт typesafe.ai и docs.typesafe.ai (сент 2026). Не факт для production: лицензия/offline/стоимость требуют дальнейшей проверки и on-device/оценочного evidence.

## Что такое Jev

Jev — первая публичная «System One» модель TypeSafe AI. Ключевое отличие от LLM: она не генерирует текст для человека, а принимает структурированные решения для кода.

- Вход: `state` (контекст) + типизированные `questions`.
- Выход: типизированные ответы + вероятности + `confidence`, без текста и парсинга.
- Все вопросы в одном запросе оцениваются параллельно и изолированно; добавление вопросов почти не меняет задержку, нет context-rot.
- «Атомарные вопросы, композиция в коде»: разбить суждение на отдельные факторы, затем комбинировать логикой кода.

## Три примитива

| Примитив | Вопрос | Возвращает |
| - | - | - |
| Choice | Выбрать вариант из списка | `choice`, `probabilities`, `confidence` |
| Score | Оценить state по рубрике | `score`, `probabilities`, `confidence` |
| Noul | Истинно ли утверждение | `noul` (0–1) |

## Заявленные метрики (с главной страницы)

- «193.6x быстрее, 444.6x дешевле» чем LLM на System One задачах (по их workflow).
- Цена $42 за миллиард входных токенов, «238x ниже Claude Fable 5.1» (заявка вендора, не независимая проверка).
- Zero hallucinations (заявление вендора), каждый ответ с confidence.
- RLCD — Reinforcement Learning for Calibrated Decisions (обучение на калиброванных решениях, а не RLHF-тексте).

## Паттерны (docs.typesafe.ai/patterns)

- Speculative Fan-Out: много вопросов одним вызовом, включая спекулятивные; код решает, что важно. Выгода — стоимость/скорость.
- Confidence-Gated Routing: confidence как вторая ось решений, для безопасных систем. Выгода — надёжность/безопасность.
- Composite Scoring: комбинировать несколько измерений в один score. Выгода — стоимость/надёжность/скорость.
- Intent Routing: классифицировать намерение пользователя и направить к нужному handler. Выгода — стоимость/скорость.

## Применимость к Pip-Boy

Jev подходит именно к слою **extraction/classification**, а не к STT. Локальный STT (sherpa/T-one) остаётся; Jev может решать:

- intent routing для capture: «это задача / событие / контакт / идея / обещание / заметка?» (Choice, Noul);
- извлечение типизированных полей с confidence (например, due date, project, priority) через Score/Choice;
- confidence-gated approval: высокая уверенность → предложение авто, низкая → запрос подтверждения; ровно наш `RequestApprove`/`ConfirmApproval`;
- дедупликация («это уже было вчера?») — Noul, с порогом;
- приоритизация Today — Choice/Score, с комбинированием в коде;
- классификация reminder-политик и связи с проектом.

Это идеально ложится на существующий порт `ExtractionEngine`: `engineId()`, `propose(transcript): List<ExtractionProposal>` — Jev адаптер возвращает proposal с confidence, а approval остаётся за пользователем (docs/architecture.md).

## Критические оговорки (не закрыты)

1. **Приватность**: внешняя модель = данные покидают устройство. Из privacy-policy (typesafe.ai/legal/privacy-policy, обновлена 2025-11-19): сервисы хостятся в США; TypeSafe (1) не обучает/не дообучает модели на входных данных (Input) и (2) не раскрывает Input третьим лицам, кроме сервис-провайдеров. Это смягчает, но НЕ снимает риск: данные транзитом уходят в США и могут быть запрошены по закону. Сырые транскрипты наружу нельзя без явного approval. Нужна схема: либо on-device/on-prem Jev (проверить, доступен ли), либо минимизация/анонимизация state (только поля решения, без raw transcript/имён/локации), либо Jev как опциональный слой с локальным fallback.
2. **Offline**: offline-first дизайн противоречит обязательной сетевой модели. Jev не должен быть единственным путём классификации.
3. **Версионирование/воспроизводимость**: `jev-latest` (OpenRouter) плавает; для повторяемости фиксировать версию.
4. **Стоимость и задержки на устройстве**: заявки вендора требуют независимой проверки на наших данных/рабочих нагрузках.
5. **Лицензия/приемлемое использование**: privacy-policy проверена (см. п.1). Terms of use (обновлены 2026-09-19): сайт/сервисы хостятся в США, ориентированы на США, обязательный binding arbitration, liability cap $100. Критично: Terms 3(c) прямо предупреждает **не отправлять конфиденциальную/проприетарную информацию** через сервисы. Это усиливает вывод п.1: сырые транскрипты и персональные данные через внешний Jev отправлять нельзя без минимизации/анонимизации state и явного approval. Остаётся acceptable-use-policy; также проверить, что именно передаётся в `state` и как хранится Input.
6. **Типы вопросов**: нужны строгие схемы типов для state и answers, чтобы codegen был типобезопасным.
